### String Matching and Regular Expression Constructs

String matching in yararun follows a syntax closely aligned with YARA's rule definitions, enabling precise pattern recognition within files. At its core, string matching is performed using literal strings or regular expressions, both of which are defined within the `strings` clause of a rule. Each string is associated with metadata such as `full`, `wide`, and `ascii`, which dictate how the string is interpreted during matching. For instance, the `full` keyword ensures that the entire content of a file must match the specified string, while `wide` indicates that the string should be treated as Unicode (UTF-16), and `ascii` restricts the string to 8-bit ASCII characters.

The syntax for defining a string is straightforward: it begins with the `string` keyword, followed by an identifier, and then the actual string value enclosed in quotation marks. For example:

```yara
string $a = "example"
```

This defines a named string `$a` that matches the literal text "example". When yararun processes this rule, it searches for the exact sequence of characters defined by the string within the file contents. If found, the rule is considered matched.

In addition to literal strings, yararun supports regular expressions through the `reg` keyword, allowing for more flexible pattern matching. Regular expressions in yararun are defined similarly to literal strings but use the `reg` prefix instead of `string`. For instance:

```yara
reg $b = /example/i
```

This defines a named regular expression `$b` that matches the word "example" in a case-insensitive manner. The `/i` modifier specifies that the match should be case-insensitive, while other modifiers such as `/m` (multi-line) or `/s` (dot matches newline) can also be used to adjust the behavior of the regular expression.

The use of regular expressions introduces additional complexity compared to literal string matching, as they allow for pattern-based searches rather than exact matches. This makes yararun particularly useful in scenarios where the target content may vary slightly but still conform to a recognizable pattern. For example, detecting a version number in a file might require a regular expression that matches digits and optional letters, such as `/v\d+\.\d+/`.

When defining strings or regular expressions, yararun also supports modifiers that influence how the pattern is matched. These modifiers can be applied directly after the string or regular expression definition. For example:

```yara
string $c = "pattern" full
```

This ensures that the entire file must match the string "pattern", rather than just containing it. Similarly, a regular expression might be defined with a modifier to control its behavior:

```yara
reg $d = /pattern/m
```

Here, the `/m` modifier allows the regular expression to match across multiple lines, treating each line as a separate string.

The combination of literal string matching and regular expressions provides yararun with a powerful toolset for identifying patterns in file content. By leveraging both approaches, users can define rules that are both precise and flexible, depending on the specific requirements of their analysis. This dual capability is essential for tasks such as malware detection, where both exact matches and pattern-based searches may be necessary to identify malicious behavior.


This defines two separate strings, `$a` and `$b`, which can be used in conjunction with other conditions or as part of a larger rule set. By defining multiple strings, users can create rules that require the presence of multiple patterns within a file, increasing the specificity of their matches.
